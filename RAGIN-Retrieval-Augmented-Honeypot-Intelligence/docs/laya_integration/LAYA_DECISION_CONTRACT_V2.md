# Laya Decision Contract V2

The V2 contract is provider-neutral at the workflow boundary. Chrollo remains
the persona/skill classifier; Laya supplies a bounded behavioral decision
signal used only to select a response-strategy context branch before Hisoka
generation.

## Typed signal

```text
LayaDecisionSignal {
    available: bool
    is_attack: bool | null
    attack_probability: float | null
    stage: enum | null
    severity: float | null
    attack_kind: string | null
    confidence: float | null
    provenance: {
        provider: string
        package_version: string | null
        repository: string | null
        checkpoint: string | null
        revision: string | null
        model_hash: string | null
        input_sha256: string
        native_schema: string
        real_model_verified: bool
    }
    latency_ms: float
}
```

## Native Laya mapping

The V2 adapter consumes the real `laya.Router.predict` output generated by
`ragin.decision.laya_runtime:LayaRuntime.infer`.

| Contract field | Native source | Rule |
|---|---|---|
| `attack_probability` | `answers.attack.noul` | Preserve the native `P(true)` value. It is not claimed to be a calibrated document-level probability. |
| `is_attack` | native `noul` decision | `true` when the native binary value is at least 0.5; this is the preregistered native binary decision, not a threshold tuned on RAGIN cases. |
| `stage` | `answers.stage.choice` | Preserve only the documented choice labels. |
| `severity` | `answers.severity.score` | Preserve the native 0--3 score when present; no probability is derived. |
| `confidence` | native confidence metadata | Record only; do not reinterpret entropy-style confidence as a calibrated probability. |
| `provenance` | runtime manifest plus input digest | No full state is logged in the decision event. |

The complete unmodified native answer object is retained under
`native_raw_output` in the decision event for provenance. The normalized fields
are the only values consumed by the policy.

## Availability and failure semantics

`available=false` is used for disabled Laya, timeout, exception, malformed
output, explicit provider `NO_SIGNAL`, missing required attack answer, or an
abstention/low-confidence marker emitted by the native API. A missing stage or
severity does not invent a value: stage-missing uses the bounded attack
containment branch, while severity-missing leaves severity null and does not
change the selected branch. Every failure returns the baseline response
strategy and cannot weaken verification or authorization.

## Non-authority boundary

Laya cannot select or bypass `FictionConsistencyVerifier`,
`HostFictionVerifier`, HITL approval, request authorization, direct serving,
or accepted-only state commit. The deterministic verifier remains the serve
gate and the only accepted state may be committed.
